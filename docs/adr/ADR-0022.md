# ADR-0022: Globally Unique, Never-Reused IDs

- Status: Accepted
- Date: 2026-03-19
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §5, §6, ADR-0023, ADR-0004, ADR-0005

## Context

Every artifact in EnterpriseSim — knowledge, context, plans, executions, evaluations,
reflections, experiences, incidents, PRs, tests — is referenced by other artifacts, and those
references are "the backbone of EnterpriseSim" (`CANON-001` §6). If an ID could be reused after
a delete, or collide across a namespace, then a citation like "`EXP-090`" would become
ambiguous over time: a reflection written last quarter might now point at a *different* object
than the one it originally meant. Reused IDs silently corrupt history and make immutability
(`ADR-0004`) and append-only accumulation (`ADR-0005`) meaningless, because the *identity*
those guarantees attach to would no longer be stable.

`CANON-001` §6 already states the rule; this ADR records the decision and its rationale so the
invariant is defended, not merely stated.

## Decision

We will enforce that all IDs are **globally unique within their namespace, zero-padded for
stable sorting, and never reused — even after deletion or deprecation**, exactly as
`CANON-001` §6 prescribes. Each prefix (`KN-`, `CTX-`, `PLAN-`, `EXP-`, `EVAL-`, `REF-`,
`ADR-`, `RFC-`, `APP-`, `TEAM-`, …) has a single assigning authority (Canon, the Architecture
Office, the AI Worker runtime, the Evaluation harness, TestRail, etc.). A deleted or deprecated
object retains its ID forever; the ID is a permanent, immutable handle to *that* object and
nothing else.

## Consequences

- **Positive.** Every historical reference remains meaningful forever: a citation resolves to
  the exact object it always meant, which is the precondition for reproducibility, auditable
  provenance (`ADR-0020`) and decision traces (`ADR-0021`).
- **Positive.** Zero-padding gives stable lexical sorting; per-namespace authorities prevent
  collisions without global coordination.
- **Negative.** ID space is monotonically consumed and never reclaimed; assigning authorities
  must be careful, because a mistakenly issued ID can never be recycled. This is a deliberate,
  accepted cost.
- **Neutral.** The canonical-ID pattern also admits realistic per-project Jira keys
  (`CHK-1421`) as cross-references, so external identifiers integrate without breaking the
  never-reused rule within ECL namespaces.
