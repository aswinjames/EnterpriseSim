# ADR-0044: Local SLM as Availability Floor / Fallback

- Status: Accepted
- Date: 2026-05-26
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-07, ADR-0009, ADR-0010, ADR-0040, ADR-0043, RFC-0029

## Context

Every model call in the ECL goes through one Model Gateway (ADR-0009), and the architecture is
model-agnostic (ADR-0010) precisely so providers are interchangeable. But interchangeability
does not by itself guarantee *availability*: ARCH-07 names **provider outage** as a system-level
failure whose mitigation is "Gateway multi-provider routing + fallback; local SLM as floor." A
Worker that can do nothing when its preferred external provider is down, rate-limited, or
unreachable is not enterprise-grade. There are also tasks where restricted data (ADR-0043)
should not egress to any external provider at all.

## Decision

We will require the Model Gateway to maintain a **local small language model (SLM) as an
availability floor and fallback**:

- When external providers are unavailable or a task's data classification forbids external
  egress (ADR-0043), the Gateway routes reasoning to the local SLM rather than failing the task.
- The SLM is reached through the same normalized Gateway contract (ADR-0011) as any other
  provider — no layer knows or cares that the floor model is local (ADR-0010).
- The SLM is a *floor*, not a peer: its capability descriptor (ADR-0012) reports lower reasoning
  capability, so Decision Intelligence tightens autonomy and escalates more readily when running
  on it (ADR-0040) — it degrades gracefully rather than pretending full capability.
- Running on the SLM is an explicit routing decision recorded in the trace (ADR-0021) and
  emitted as a signal (ADR-0038); reasoning-cost budgets (ADR-0039) account for the cheaper
  floor.

## Consequences

- Positive: availability floor — Workers keep functioning (at reduced capability) through
  provider outages; a data-sovereign path exists for restricted-classification tasks that must
  not leave the boundary.
- Positive: lowers the cost floor for trivial reasoning steps (pairs with cheap-first routing,
  ADR-0039).
- Negative: quality drop on the floor model — some tasks that succeed on a high-reasoning
  provider will only reach a partial result or escalate on the SLM; this must be transparent,
  not hidden, and is why autonomy tightens automatically.
- Negative: operating a local SLM adds infrastructure and maintenance the Gateway must own.
- Neutral: the SLM's presence reinforces the model-agnostic invariant — the *same* accumulated
  Knowledge and Experience apply whether reasoning runs on a frontier provider or the local
  floor (ARCH-07).
