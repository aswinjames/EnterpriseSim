# ADR-0046: Freshness SLAs for Knowledge

- Status: Accepted
- Date: 2026-06-09
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-02, ARCH-07, ADR-0007, ADR-0004, ADR-0036, ADR-0047

## Context

Knowledge (KN-###) is the ECL's governed truth and the only source of truth (ADR-0007); it is
immutable once published (ADR-0004). But truth about a living enterprise goes stale: a runbook
describes a service that has since been re-architected, an API contract predates a new major
version, a standard is superseded. ARCH-07 names **memory rot** — Knowledge stale, Experience
overfit — as a system-level failure, with freshness SLAs as the mitigation for the Knowledge
side. A stale Knowledge object is worse than a missing one, because it is *cited as
authoritative* and a Worker will trust it.

Because Knowledge objects are immutable, freshness cannot mean "edit in place." It must mean a
governed review-and-supersede lifecycle with an explicit expected-freshness horizon.

## Decision

We will attach **freshness SLAs to Knowledge**, per ARCH-02:

- Each `KnowledgeObject` carries a freshness horizon / review-by date appropriate to its
  volatility (a PCI standard reviewed more often than company history).
- When a Knowledge object passes its review-by date it is flagged **stale**; its retrieval
  authority is lowered so the Context Layer and Decision Intelligence weigh it as provisional
  (composable confidence, ADR-0013), and it is surfaced for governed review.
- Review either re-affirms the object (resetting the horizon) or supersedes it with a new
  immutable version (ADR-0004); the old version is retained for lineage, never silently deleted.
- Freshness state is a signal (ADR-0038); promotion of Experience into Knowledge (ADR-0036) sets
  an initial freshness horizon on the newly promoted object.

## Consequences

- Positive: prevents stale truth from being trusted as current; degrades authority gracefully
  rather than either trusting blindly or hard-failing; keeps the durable-memory half of the
  flywheel honest alongside Experience decay (ADR-0047).
- Positive: pairs with immutability (ADR-0004) — freshness is handled by supersession and
  authority weighting, not mutation, preserving lineage.
- Negative: review burden — someone (human or a governance Worker) must action stale flags;
  unreviewed stale Knowledge accumulates if the process is neglected, so review throughput must
  be monitored.
- Negative: choosing the right horizon per object is judgment; too short creates review churn,
  too long lets rot accumulate.
- Neutral: freshness is about *currency*, distinct from *correctness* — a fresh object can still
  be wrong (caught by contradiction and reflection) and a stale one can still be right (caught
  by re-affirmation).
