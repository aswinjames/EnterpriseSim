# ADR-0028: Python as SDK Reference Language

- Status: Accepted
- Date: 2026-02-10
- Deciders: Architecture Office (TEAM-090)
- Related: ADR-0027, ADR-0029, ADR-0030, ADR-0010

## Context

The ECL architecture (ARCH-01…ARCH-07) is language-neutral prose. To make it precise and
buildable, EnterpriseSim ships an SDK: an abstract contract layer that a team of senior
engineers can build against. That SDK must be written in some language, and the choice sets
the typing surface, the tooling, and the audience for the whole project.

MCG's production services are polyglot (Java, Go, Kotlin, Scala, TypeScript, C#/.NET; see
CANON-001 §3). The SDK is deliberately *not* a production runtime for those services — it is
the reference expression of the ECL contracts, mirroring the JSON Schemas (ADR-0027) as typed
interfaces. We need a language with mature structural and nominal typing, a first-class role in
the AI/ML ecosystem (where Workers and model gateways are built), and high readability for a
public benchmark.

## Decision

We will use **Python** as the reference language for the EnterpriseSim SDK, using
`typing.Protocol` for structural interfaces and `abc.ABC` for nominal ones (ADR-0029), with
every method body left as `...` — the SDK defines *what*, never *how*.

Python is the *reference* expression, not an exclusivity mandate. Because the source of truth
for object shape is the JSON Schema (ADR-0027) and contracts are open standards (ADR-0026),
implementations in other languages are first-class as long as they satisfy the same schemas and
interface semantics. Only `sdk.models` may touch provider SDKs, preserving model-agnosticism
(ADR-0010).

## Consequences

- Positive: broad accessibility — Python is the lingua franca of AI/ML practitioners who will
  build and benchmark Workers; low barrier to reading and contributing.
- Positive: mature typing (`Protocol`, `ABC`, generics) expresses the ECL's abstraction-first
  design cleanly; excellent JSON Schema tooling for keeping `objects.py` in sync with `schemas/`.
- Negative: Python's runtime performance and the GIL make it a poor choice for MCG's
  latency-critical Tier 0 services — but the SDK is a contract layer, not that runtime, so this
  is out of scope.
- Negative: structural typing (`Protocol`) is checked statically, not enforced at runtime;
  schema validation (ADR-0027) remains the runtime guarantee.
- Neutral: other-language ports carry a synchronization cost against the Python reference and
  the schemas; the schema-as-source-of-truth rule keeps that cost bounded.
