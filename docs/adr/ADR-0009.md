# ADR-0009: Single Model Gateway for All Provider Access

- Status: Accepted
- Date: 2026-02-02
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §8 (principle 9), ARCH-07, ADR-0002, ADR-0010, ADR-0012

## Context

The ECL must remain model-agnostic (`ADR-0010`): OpenAI, Anthropic, Gemini, open-source
models via vLLM, and local SLMs must be interchangeable. If provider SDKs are imported
wherever a model is called — in the Context Layer, in Decision Intelligence, in the Evaluation
Layer's model-assisted judgments — then vendor specifics (auth, prompt formats, tool-calling
conventions, response shapes, retry semantics) leak across the whole system. Swapping a
provider then becomes a cross-cutting change touching every layer, and "model-agnostic"
degrades to an aspiration.

We must decide how many components are allowed to talk to a model provider.

## Decision

We will route **every model call in the entire ECL through a single Model Gateway
(`ARCH-07`)**. No layer other than the Gateway may import a provider SDK or hold
provider-specific logic. The Gateway is the one place that renders a structured context
object (`ADR-0011`) into a provider-specific prompt, performs the call, and normalizes the
response back into the ECL's own vocabulary. It also owns provider auth, retries, fallback,
multi-provider routing, and the capability descriptors used for negotiation (`ADR-0012`).
Adding or swapping a provider changes only a Gateway *adapter* and routing config — never a
layer.

## Consequences

- **Positive.** Model-agnosticism becomes a *structural invariant* (`ADR-0010`) enforced by a
  single import boundary, not a convention. A provider migration is a Gateway change; every
  `CTX-###`, `PLAN-###`, rubric and lesson is untouched and immediately effective under the
  new provider.
- **Positive.** Cross-cutting concerns — cost accounting, latency tracking, rate limiting,
  fallback to a local SLM as an availability floor — are implemented once, at the choke point.
- **Negative.** The Gateway is on the critical path of every task and is a single point of
  failure; it must be highly available and must not itself become a place where layer logic
  accretes. Multi-provider routing and local-SLM fallback mitigate the availability risk.
- **Neutral.** Provider-side conveniences (server-side threads, prompt caching) are usable only
  as optimizations *inside* the Gateway, consistent with statelessness (`ADR-0002`).
