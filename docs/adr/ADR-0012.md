# ADR-0012: Capability Negotiation Over Provider Assumptions

- Status: Accepted
- Date: 2026-02-12
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-07, ADR-0009, ADR-0010, ADR-0039, ADR-0044

## Context

Models differ in ways that matter to the ECL: context-window size, native tool-calling versus
none, structured-output support, cost per token, and latency. A tempting shortcut is to code to
the *current* model's behavior — assume a 200k window, assume native tool-calling, assume JSON
mode — because it is simpler. But those assumptions are exactly what break when a provider is
swapped or when DI routes a trivial task to a small local SLM (`ADR-0044`) with a smaller
window and no tool-calling. Hard-coded assumptions turn a routing decision into a latent bug.

We must decide how the ECL adapts to heterogeneous model capabilities.

## Decision

We will require **capability negotiation**: the Model Gateway publishes a **capability
descriptor** per model — context window, tool-calling support, structured-output mode, cost,
latency — and Decision Intelligence and the Context Layer *adapt to the advertised
capabilities* rather than assuming any provider's behavior. Context budgeting reads the window
from the descriptor (`ADR-0011`); DI decides whether to use native tool-calling or emulate it
based on the descriptor; routing (`ADR-0039`) trades cost/latency/quality using descriptor
values. No layer assumes a capability the descriptor does not advertise.

## Consequences

- **Positive.** A model swap or a route to a smaller model degrades gracefully: the ECL budgets
  to the real window and emulates missing features instead of failing or silently truncating.
  This makes model-agnosticism (`ADR-0010`) robust across genuinely different models, not just
  similar large ones.
- **Positive.** Cost- and latency-aware routing and reasoning budgets (`ADR-0039`) have a
  principled input, enabling "use the cheapest model that can do this task."
- **Negative.** The ECL must implement fallbacks for absent capabilities (e.g., tool-call
  emulation, hierarchical/streaming context for small windows), which is more engineering than
  assuming a rich model. Descriptors must be kept accurate or negotiation is misled.
- **Neutral.** Capability descriptors become a versioned contract of their own; adding a new
  capability dimension is an additive, backward-compatible change under the SDK's SemVer policy.
