# ADR-0006: Context Is Ephemeral

- Status: Accepted
- Date: 2026-01-22
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §9 (Stage 2), ARCH-01, ADR-0002, ADR-0004, ADR-0020

## Context

The Context Layer (`ARCH-01`) assembles the right, minimal, sufficient working set for **one
task** and holds it **only for that task's duration**. A `CTX-###` is a snapshot: it pulls
together a subset of knowledge, applicable experiences, target code and live enterprise state
at a moment in time. The danger is that this convenient, task-specific bundle starts to feel
authoritative — that a fact "in the context" gets treated as durable truth, or that a stale
context is reused across tasks because reassembling it is expensive.

If ephemeral context is allowed to masquerade as durable memory, two invariants break: the
single-source-of-truth property of Knowledge (`ADR-0007`) is undermined, and reproducibility
suffers because nobody can tell whether a Worker acted on governed truth or on a stale local
copy.

## Decision

We will treat context as **strictly ephemeral**. A `CTX-###` is born when a task starts,
enriched as the Worker reasons (the Active self-loop in `ARCH-01` — iterative re-retrieval is
allowed *within* a task), and **archived, never authoritative**, when the task ends. Context is
never a source of truth and is never carried forward as durable memory; the next task
reassembles fresh context from Knowledge (`ARCH-02`), Experience (`ARCH-03`) and live state.

Crucially, "ephemeral" applies to the context *as truth*, not to its *provenance record*: the
provenance manifest — what was retrieved, from where, why, and what was dropped — is preserved
and handed to Evaluation (`ARCH-04`) and the Learning Engine (`ARCH-05`). We archive the
evidence of assembly; we do not retain the working set as authoritative.

## Consequences

- **Positive.** Truth stays singular and current: Workers act on freshly-retrieved governed
  knowledge and live state, not on a stale cached bundle. Volatile facts (code, inventory, SLO
  status) are read fresh, avoiding the "stale context" failure mode.
- **Positive.** Preserving provenance while discarding the working set gives the best of both:
  reflection can diagnose "the fix was in a doc we dropped" without context ever becoming a
  competing store of truth.
- **Negative.** Every task pays reassembly cost; there is no free reuse of a prior task's
  context. Predictive pre-fetch and cross-Worker fragment reuse (validated against live state)
  are the sanctioned optimizations, not blanket caching.
- **Neutral.** Context confidence (coverage/sufficiency) is emitted and consumed each task
  (`ADR-0013`), reinforcing that context is evaluated per task rather than trusted by default.
