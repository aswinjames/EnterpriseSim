# ADR-0004: Knowledge Objects Are Immutable Once Published

- Status: Accepted
- Date: 2026-01-15
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §9 (Stage 1), ARCH-02, ADR-0020, ADR-0022, ADR-0046

## Context

The Knowledge Layer (`ARCH-02`) is the enterprise's governed truth: architecture docs,
business rules, runbooks, API contracts, and validated learnings. Workers *cite* knowledge
and act on it, and evaluations later judge whether they respected it. If a knowledge object
could be edited in place after publication, a citation like "per `KN-045`" would be
ambiguous — which version? — and a past decision trace could no longer be reproduced, because
the fact it relied on may have silently changed underneath it.

We need knowledge that is simultaneously *durable and citable* and *able to evolve* as MCG
changes. Those goals conflict only if we treat "a knowledge object" as a single mutable
record.

## Decision

We will make published knowledge objects **immutable**. A `KN-###` at a given version is
frozen once its status becomes `published`; it is never mutated in place. Evolution happens by
producing a **new version** (a new immutable record under the same `KN-###` identity) through
the governed lifecycle — Drafted → InReview → Approved → Published (`ARCH-02`) — with the
prior version retained. Superseded and deprecated versions are **never hard-deleted**; they
are excluded from default retrieval but kept for historical and audit fidelity, mirroring
canon's "IDs are never reused" rule (`ADR-0022`).

Every citation therefore resolves to a specific, unchangeable version, and every published
fact carries provenance (`ADR-0020`) and a freshness SLA (`ADR-0046`).

## Consequences

- **Positive.** Decision traces, context objects and evaluations are reproducible forever: the
  exact knowledge a Worker reasoned over can always be reconstructed at the version it saw.
- **Positive.** Concurrent readers never observe a half-updated fact; governance reviews a
  complete new version rather than a diff applied live.
- **Negative.** Correcting even a typo requires a new version and a governance pass, which is
  heavier than an in-place edit. Fast-moving facts must lean on live enterprise state in the
  Context Layer (`ARCH-01`) rather than on frequently re-versioned knowledge.
- **Neutral.** Storage grows monotonically with versions; this is acceptable and is the same
  trade-off the Experience Layer makes (`ADR-0005`). Non-semantic annotations live in the open
  `metadata` field so they never require a new version to record.
