# ADR-0002: The LLM Is Stateless

- Status: Accepted
- Date: 2026-01-08
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §9, ARCH-07, ADR-0003, ADR-0006, ADR-0009

## Context

Every design choice in the ECL descends from one hard fact about the reasoning engine we
build on: **a large language model has no memory, no enterprise knowledge, no accumulated
experience, and no ability to improve itself between calls.** Whatever a model "knows" at
inference time was either baked into its weights by its vendor or handed to it in the prompt.
It forgets everything the instant a call returns.

There is a tempting alternative framing — treat the model as a stateful agent that
"remembers" a conversation or a project — but that state is an illusion maintained by
whatever feeds the prompt. Building the architecture as if the model were stateful couples us
to a specific provider's session mechanics, hides where memory actually lives, and makes the
system impossible to reason about, audit, or benchmark fairly across providers.

We must decide, as a foundational stance, whether the ECL treats the model as stateful or
stateless.

## Decision

We will treat the LLM as **strictly stateless**: a pure function from an assembled input to a
reasoned output, holding no durable state of its own. Every unit of understanding a Worker
uses at runtime must be *deliberately assembled and injected* by the ECL (the Context Layer,
`ARCH-01`) and every durable memory must live *outside the model* — in the Knowledge Layer
(`ARCH-02`) and Experience Layer (`ARCH-03`). No ECL component may assume a model retains
anything across calls, nor rely on provider-side conversation state as a source of truth.

This is the axiom from which the rest of the catalog follows: because the model is stateless,
learning must live outside it (`ADR-0003`), context must be ephemeral and reconstructed each
task (`ADR-0006`), and all provider access is mediated so statelessness is enforced, not
hoped for (`ADR-0009`).

## Consequences

- **Positive.** The architecture becomes model-agnostic by construction: any model that maps
  input to output can be swapped in, because none of the organization's competence is trapped
  in a vendor's weights or session store.
- **Positive.** Behavior is reproducible and auditable — identical assembled input yields a
  comparable result, which is what makes EnterpriseSim a benchmark rather than a demo.
- **Negative.** The ECL must do real work every task to reconstruct what a stateful system
  would keep "for free": retrieval, assembly, and budgeting are now first-class costs.
- **Neutral.** Provider features that cache or persist state (threads, memory APIs) may be
  used only as *performance optimizations behind the Gateway*, never as authoritative memory.
