# ADR-0034: Loop Closure as the Definition of Learning

- Status: Accepted
- Date: 2026-03-19
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-05, ARCH-07, ADR-0003, ADR-0035, ADR-0036, ADR-0038

## Context

EnterpriseSim's entire thesis is that a stateless model (ADR-0002) improves because learning
lives outside it (ADR-0003): the Learning Engine converts evaluated executions into
reflections, experiences and promoted knowledge that reshape future context. But it is easy to
*appear* to learn — to write reflections and experiences that no future task ever uses. Writing
a lesson is cheap; changing behavior is the point. ARCH-05 is explicit that the terminal state
of the learning lifecycle is **LoopClosed**, not "lesson written," and that a lesson which
never changes a future execution is by definition not learning.

We need a definition of "learning" that is measurable and honest, so the continuous-improvement
flywheel (CANON-001 §9.8) is a real signal and not a vanity metric.

## Decision

We will define **learning as loop closure**: a lesson counts as learned only when it
demonstrably changes a later execution. The Learning Engine measures itself on **loop-closure
rate** — the fraction of lessons that measurably altered a subsequent task — and this is a
first-class signal on the Signals Bus (ADR-0038).

Concretely, an experience or policy update is not credited as "learning" until a later
execution retrieves/applies it (traceable via provenance) and the outcome reflects it — for
example, `EXP-090` produced by `REF-0019` is credited only when `PR-0312` applies it and passes
(ARCH-05, Example B). Reflections and experiences may exist as candidates before closure, but
the improvement metric counts closed loops.

## Consequences

- Positive: an honest, gameable-resistant definition of learning; the flywheel becomes a
  measurable trend of `EVAL-###` lift per task type (ARCH-07 improvement signals) rather than a
  count of documents written.
- Positive: forces the Learning Engine to actually alter retrieval/planning policies (ADR-0035,
  Context and Decision Intelligence heuristics), not just archive insights.
- Negative: closure is delayed and its attribution is hard — the future task that would close a
  loop may be weeks away, or a lesson may be partially responsible among several; measurement
  must tolerate latency and shared credit.
- Negative: some genuinely useful lessons (rare-situation warnings) may rarely close because the
  situation recurs seldom; these are retained (ADR-0047) but under-counted, so loop-closure rate
  must be read alongside coverage, not alone.
- Neutral: pairs with regression-prevention tracking in Evaluation — a closed loop that
  prevents a known recurrence is the strongest evidence of learning.
