# ADR-0027: JSON Schema Draft 2020-12 as Contract Language

- Status: Accepted
- Date: 2026-02-05
- Deciders: Architecture Office (TEAM-090)
- Related: ADR-0026, ADR-0023, ADR-0032, ADR-0033, RFC-0021

## Context

Every ECL object — `KnowledgeObject` (KN-###), `ContextObject` (CTX-###), `PlanningObject`
(PLAN-###), `EvaluationObject`, `ReflectionObject`, `ExperienceObject` and the worker
artifacts — needs an authoritative, machine-checkable shape that is independent of the SDK's
implementation language (ADR-0028). The schema, not the code, must be the source of truth for
object shape so that any language or tool can validate an artifact and preserve referential
integrity (ADR-0023).

We need a schema language that: composes a shared base (IDs, confidence, provenance,
timestamps) into every object; forbids stray fields without breaking inheritance; expresses
canonical ID patterns from CANON-001 §6; and is a stable, open standard (ADR-0026).

## Decision

We will author all ECL object contracts in JSON Schema **Draft 2020-12**, and treat those
schemas in `schemas/` as the source of truth for object shape (the SDK Protocols in
`objects.py` mirror them, not the reverse).

We adopt Draft 2020-12 specifically for its features:

- **`unevaluatedProperties: false`** lets an object compose the shared `eclObjectBase` via
  `allOf` *and* still forbid unknown fields — something `additionalProperties` cannot do across
  an `allOf` boundary. Every object schema closes with this pattern.
- **`$defs`, `$ref` and `$id`** support a schema registry keyed by `$id` so relative references
  resolve without network access.
- **`prefixItems` / `$dynamicRef`** give precise array and reuse semantics where needed.

Each instance carries `schema_version` matching `^2020-12\.v\d+$`, tracked by
`sdk.SCHEMA_VERSION`. A dependency-free structural validator is maintained in the test suite
for CI environments that lack a network or a 2020-12-capable validator.

## Consequences

- Positive: strict, composable validation; open, widely implemented standard; one contract
  validated identically across languages.
- Positive: the `metadata` escape hatch stays additive and non-semantic, keeping core
  validation strict while allowing extension (ties to ADR-0026).
- Negative: some validator libraries still lag on full Draft 2020-12 support (notably
  `unevaluatedProperties`); we mitigate with a pinned reference validator and the in-repo
  structural fallback.
- Negative: 2020-12 is more subtle than earlier drafts; contributors must understand
  `allOf` + `unevaluatedProperties` interaction to avoid accidentally-open objects.
- Neutral: schema versioning and evolution are governed separately by RFC-0021 and ADR-0033;
  SemVer semantics for schemas are defined in ADR-0032.
