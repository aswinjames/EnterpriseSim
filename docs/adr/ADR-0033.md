# ADR-0033: Schema Evolution via Expand-Contract

- Status: Accepted
- Date: 2026-03-12
- Deciders: Architecture Office (TEAM-090)
- Related: ADR-0027, ADR-0032, ADR-0023, ADR-0022, CANON-001 §7.4, RFC-0021

## Context

ECL objects are long-lived and cross-referenced (ADR-0023): a `ReflectionObject` points at an
`EvaluationObject`, which points at a PR and a `PlanningObject`, and so on. Instances are
immutable records — Knowledge is immutable once published (ADR-0004), Experience is append-only
(ADR-0005). We cannot rewrite existing instances in place when a schema changes, and we cannot
afford a "flag day" where every producer and consumer must upgrade at once. CANON-001 §7.4
already mandates backward-compatible, expand-contract database migrations so rollback never
needs a schema down-migration under fire; the ECL schemas need the same discipline.

## Decision

We will evolve schemas using the **expand-contract** (parallel-change) pattern, per RFC-0021:

1. **Expand.** Add new fields as optional first; never introduce a required field or remove a
   field in a single step. This is a MINOR change (ADR-0032).
2. **Migrate.** Dual-write the old and new shapes; backfill as needed. Producers move to the
   new shape while readers tolerate both. Instances are never rewritten in place — a new
   version is a new record, preserving immutability (ADR-0004/0005) and IDs (ADR-0022).
3. **Contract.** Only once no producer emits the old shape do we make a field required or
   remove the old field — a MAJOR change (ADR-0032). Validators accept the current and previous
   major during the migration window.

A migration that would break a cross-reference is forbidden without an ADR, because referential
integrity is invariant (ADR-0023, ADR-0022).

## Consequences

- Positive: zero-downtime, rollback-safe evolution; readers never break mid-migration; matches
  CANON-001 §7.4 and preserves the immutability/append-only invariants.
- Positive: pairs with SemVer (ADR-0032) — breaking changes are staged through additive minors
  before the contracting major, reducing abrupt MAJOR churn.
- Negative: transitional dual-write and tolerant-reader logic add complexity and a period where
  two shapes coexist; the migration window must be actively closed, not left open forever.
- Negative: longer change cycles for contract changes than a naive in-place rewrite would take.
- Neutral: `metadata` remains the sanctioned place for additive, non-semantic annotations
  (ADR-0027), absorbing many extensions without any schema change at all.
