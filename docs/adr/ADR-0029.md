# ADR-0029: Abstract Interfaces Over Concrete Coupling (Protocols/ABCs)

- Status: Accepted
- Date: 2026-02-17
- Deciders: Architecture Office (TEAM-090)
- Related: ADR-0028, ADR-0010, ADR-0009, ADR-0030, ARCH-07

## Context

The ECL's central invariant is model-agnosticism (ADR-0010): providers, stores, retrievers,
tools and rubrics must be swappable without touching the layers that use them. ARCH-07 makes
this a *structural* guarantee — only the Model Gateway imports provider SDKs; no layer depends
on a concrete provider. That guarantee only holds if the SDK's layers depend on abstractions,
not implementations.

If Decision Intelligence imported a specific vector database, or the Context Assembler
imported a specific LLM client, the swap-a-provider promise (ARCH-07, Example B) and the
fair-benchmark promise would both break.

## Decision

We will express every extension point in the SDK as an **abstract interface** and require
callers to depend on that interface, never on a concrete implementation:

- Use `typing.Protocol` for structural contracts where duck-typing and third-party
  implementations are expected (e.g. `Retriever`, `Tool`, `ModelProvider`).
- Use `abc.ABC` for nominal contracts where identity and a shared base matter (e.g.
  `KnowledgeStore`, `Evaluator`, `Reflector`).
- Concrete implementations are wired in at the edges — via plugin entry points (ADR-0030) — and
  the runtime composes them. The single Model Gateway (ADR-0009) is the sole point of provider
  contact.

## Consequences

- Positive: implementations (model providers, vector/graph/document stores, tools) are
  swappable without changing any consuming layer — the mechanism behind ADR-0010 and the
  benchmark's fairness.
- Positive: testability — layers can be exercised against fakes/fixtures, which is a
  precondition for deterministic replay (ADR-0037) and reproducible benchmarks (ADR-0048).
- Positive: enforces the dependency direction of ARCH-07 (agency concentrated in Decision
  Intelligence; providers outside the boundary).
- Negative: more indirection and upfront interface design; a poorly chosen abstraction leaks
  and must be revised (a schema/contract change, governed by SemVer, ADR-0032).
- Neutral: `Protocol` is checked statically; runtime conformance still relies on schema
  validation (ADR-0027) and capability negotiation (ADR-0012).
