# ADR-0038: Signals Bus for Cross-Layer Observability

- Status: Accepted
- Date: 2026-04-14
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-07, ADR-0026, ADR-0034, ADR-0021, RFC-0028

## Context

Every ECL layer emits signals — Context coverage and dropped candidates, Evaluation gate
failures, Decision Intelligence replan/escalation/guardrail activations, Experience application
and contradiction rates, Learning Engine loop-closure and root-cause accuracy (ARCH-01…ARCH-06).
Two very different consumers need these signals: **observability/audit** (humans operating and
inspecting Workers) and the **Learning Engine** itself (which consumes cross-cutting telemetry
to find systemic patterns). If each layer wired point-to-point integrations to each consumer,
the architecture would couple tightly and the Learning Engine could not see the whole picture.

ARCH-07 already posits a unified signals bus emitting per-layer signals, end-to-end task signals
(success rate, time-to-completion, reasoning cost, escalation/autonomy rate) and improvement
signals (the `EVAL-###` trend that *is* the flywheel measurement).

## Decision

We will route all cross-layer observability through a single **Signals Bus**, per RFC-0028.
Layers publish signals as events onto the bus rather than calling consumers directly; the bus
is consumed by observability/audit tooling and by the Learning Engine.

- Signal events use an open, CloudEvents-compatible envelope (ADR-0026) with a governed schema,
  carrying the emitting layer, task and object IDs (referential integrity, ADR-0023), and a
  sensitivity classification (ADR-0043).
- Signals are the source for the ECL's defining metrics: loop-closure rate (ADR-0034),
  improvement trend, reasoning cost (ADR-0039), escalation rate (ADR-0040) and guardrail
  activations (ADR-0041).
- Decision traces (ADR-0021) and provenance (ADR-0020) remain the authoritative per-task record;
  the bus carries the aggregate, streaming observability layered on top.

## Decision boundary

The bus is for observability and learning telemetry, not for control-flow orchestration — that
remains Decision Intelligence's job (ADR-0008). Emitting a signal never drives a Worker action.

## Consequences

- Positive: decoupled, fan-out observability; the Learning Engine sees cross-cutting patterns
  it could not see per-layer (systemic-pattern detection, ARCH-05); one place to measure the
  flywheel.
- Positive: open envelope keeps the bus tool-agnostic and portable (ADR-0026).
- Negative: signal volume can be high; the bus needs sampling/retention policy and its event
  schema needs the same versioning governance as other contracts (ADR-0032).
- Negative: a governed signal schema is one more contract to maintain; undisciplined ad-hoc
  signals would erode its value.
- Neutral: because signals carry classification, some are restricted; consumers see only
  signals their policy permits (ADR-0043).
