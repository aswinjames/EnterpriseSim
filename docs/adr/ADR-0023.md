# ADR-0023: Referential Integrity Across Artifacts

- Status: Accepted
- Date: 2026-03-23
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §6, ARCH-07, ADR-0020, ADR-0022, ADR-0033

## Context

The ECL loop produces a web of cross-referencing artifacts: a `CTX-###` cites `KN-###` and
`EXP-###`; a `PLAN-###` applies `EXP-###`; an `EVAL-###` scores a `PR-####` against a
`PLAN-###` and checks against `EXP-###`; a `REF-###` reflects on an `EVAL-###` and creates an
`EXP-###`; a promoted `EXP-###` links to `KN-###`. This graph *is* the demonstration
EnterpriseSim exists to make — the loop from knowledge to experience and back. If references
can dangle (point at a non-existent or wrong-typed ID), the loop breaks: provenance
(`ADR-0020`) leads nowhere, hybrid graph retrieval (`ADR-0019`) traverses into holes, and the
benchmark's central artifact — a fully-linked task loop — cannot be trusted.

We must decide whether cross-references are validated or best-effort.

## Decision

We will require **referential integrity across all artifacts**: every cross-reference must use
a canonical ID (`ADR-0022`) that resolves to an existing object of the expected type. The JSON
Schemas (`schemas/`) constrain ID *shape*; a validation pass additionally checks that
references *resolve* and are type-correct (e.g., `EvaluationObject.plan` is a `PLAN-###`,
`.execution` is a `PR-####`). References are never silently rewritten; because IDs are
immutable and never reused, a resolved reference stays valid forever. A schema migration that
would break a reference requires an ADR (`ADR-0033`, expand-contract), never an in-place
change that orphans a link.

## Consequences

- **Positive.** The full loop (`KN → CTX → PLAN → EXE → EVAL → REF → EXP → KN`) is guaranteed
  navigable and inspectable — the property the `CHK-1421` worked example relies on and the
  substrate for graph retrieval and audit.
- **Positive.** Integrity violations are caught at validation time rather than surfacing as
  mysterious dead ends during reflection or benchmarking.
- **Negative.** Validation must resolve references (not just pattern-match IDs), which needs a
  registry/index of all artifacts and makes validation more than a local, per-file check.
- **Neutral.** Deprecated objects still resolve (they are retained, `ADR-0004`/`ADR-0005`), so
  integrity holds across the full history, not just the currently-active set.
