# ADR-0018: Versioned Rubrics for Reproducible Benchmarks

- Status: Accepted
- Date: 2026-03-05
- Deciders: Architecture Office (TEAM-090)
- Related: CANON-001 §2.5 (QE, TEAM-050), ARCH-04, ADR-0015, ADR-0048

## Context

Evaluation applies per-task-type rubrics (e.g., `RUBRIC-feature-change`, `RUBRIC-case-
resolution`) that define what to score and how to weight it. Rubrics must evolve — they are
refined against real incidents and improved as QE learns what actually predicts quality. But if
a rubric changes silently, then two evaluations run months apart are no longer comparable: a
score drop might reflect a worse Worker or just a stricter rubric. "Benchmark drift" of this
kind quietly invalidates every longitudinal and cross-Worker comparison, which are the whole
point of the benchmark.

We must decide how rubrics change without destroying comparability.

## Decision

We will **version every rubric** and record the exact rubric version in each `EVAL-###`
(e.g., `{ id: RUBRIC-feature-change, version: 3 }`). Rubrics are owned by Quality Engineering
(`TEAM-050`) with the Architecture Office, reviewed against incidents, and changed only by
issuing a new version — never edited in place. Comparisons are only made *within* a rubric
version, or with an explicit, documented mapping when a version boundary is crossed. A benchmark
result is meaningless without its rubric version, so recording it is mandatory (`ADR-0048`).

## Consequences

- **Positive.** Longitudinal and cross-Worker comparisons stay valid: a score change within a
  rubric version reflects the Worker, not a moved goalpost. The continuous-improvement flywheel
  can be *measured* because the ruler is stable.
- **Positive.** Rubrics can still improve; improvement is explicit and dated, and old results
  remain interpretable at the version they were scored under.
- **Negative.** Rubric changes now require version discipline and, for meaningful trend lines,
  re-scoring historical executions under the new version — extra work QE must budget for.
- **Neutral.** Versioned rubrics mirror the immutability discipline applied to knowledge
  (`ADR-0004`) and schemas (SemVer, full catalog `ADR-0032`); it is the same "freeze then
  supersede" pattern in the evaluation domain.
