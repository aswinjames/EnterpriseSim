# ADR-0011: Store Structured Context Objects, Not Prompt Strings

- Status: Accepted
- Date: 2026-02-09
- Deciders: Architecture Office (TEAM-090)
- Related: ARCH-01, ARCH-07, ADR-0009, ADR-0010, ADR-0020

## Context

The Context Layer's output is what the model reasons over. The naive representation is a
*prompt string* — the fully rendered text ready to send to a provider. But a prompt string is
provider-specific (each vendor has different formatting, system/role conventions, and
tool-calling encodings), opaque (you cannot cleanly query "which knowledge items are in here?"
or "what was dropped?"), and lossy for provenance and evaluation. If context is stored as a
string, the Context Layer is silently coupled to a provider and the reasoning inputs become
hard to audit.

We must decide the representation of a `CTX-###`.

## Decision

We will store context as a **structured context object** (`CTX-###`) — a schema-conformant
document (JSON per the `schemas/`) listing included items, excluded items, each with source,
relevance score and inclusion rationale, plus task intent, model budget and coverage
confidence — **not** a rendered prompt string. Rendering the structured object into a
provider-specific prompt is done exclusively by the Model Gateway (`ADR-0009`) at call time.

This keeps the Context Layer, and every layer that reads context, entirely provider-free
(`ADR-0010`) and makes context inspectable: provenance (`ADR-0020`) is a queryable property of
the object, not text buried in a prompt.

## Consequences

- **Positive.** The same `CTX-###` renders correctly against any provider, so context assembly
  is reusable across a model swap with zero change — the concrete mechanism behind
  model-agnosticism.
- **Positive.** Evaluation and reflection can inspect exactly what the Worker was given and
  what was dropped, because those are structured fields; "the fix was in a doc we dropped"
  becomes a queryable diagnosis, not forensic prompt-reading.
- **Negative.** There is a rendering step and a schema to maintain; a bug in rendering can
  misrepresent a well-formed context, so the Gateway's renderer needs its own tests. Budget
  must be enforced on the structured object *before* rendering, never via provider truncation.
- **Neutral.** Structured context is slightly more verbose to author and debug than raw text,
  but that verbosity *is* the auditability the benchmark requires.
