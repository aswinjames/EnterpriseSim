# ADR-0051: Extend ID Namespaces for the Reference Learning Corpus (RUN, DEC, EXE)

- Status: Accepted
- Date: 2026-07-10
- Deciders: Architecture Office (TEAM-090)
- Related: ADR-0022 (Globally Unique, Never-Reused IDs), ADR-0033 (Expand-Contract), ADR-0050 (Canon Supremacy — Changes via ADR Only), CANON-001 §6, RFC-0021 (Schema Versioning)

## Context

The Reference Implementation Phase generates a learning corpus of complete Enterprise
Worker executions (see `corpus/`). Each execution embeds schema-valid ECL objects for every
stage of the lifecycle: a `ContextObject`, `PlanningObject`, `WorkerDecision`,
`WorkerExecution`, `EvaluationObject`, `ReflectionObject` and an experience update.

`WorkerDecision`, `WorkerExecution` and the run bundle require globally-unique `id`s, but the
frozen `canonicalId` pattern in `schemas/common.schema.json` (per `CANON-001` §6) enumerates
no namespace for worker runs, decisions, or execution records. `ADR-0050` established that
canon is authoritative and that changes are introduced through an ADR. `ADR-0050`'s own
consequences anticipate that "future ADRs (ADR-0051+) extend it." This is that extension.

The change is **expand-only** (`ADR-0033`): it adds alternatives to a regex; every existing
identifier still validates, and no existing artifact changes. This is exactly the safe,
additive evolution the schema-versioning policy prescribes.

## Decision

We will extend the `CANON-001` §6 ID conventions and the `canonicalId` definition in
`schemas/common.schema.json` with three new globally-unique, never-reused namespaces used by
the reference learning corpus and by Enterprise Worker runtimes:

- `RUN-####` — a single Enterprise Worker run (one execution of the ECL loop for one task).
- `DEC-####` — a decision emitted by Decision Intelligence onto a run's decision trace.
- `EXE-####` — an execution record (a plan step or plan carried out via tools).

The `canonicalId` pattern gains `RUN|DEC|EXE` as accepted prefixes. All other ID rules
(uniqueness, never-reused, referential integrity) apply unchanged. This is a `2020-12.v1`
additive change; no schema major-version bump is required because it is backward compatible.

## Consequences

- **Positive:** The corpus can embed fully schema-valid decision, execution and run objects
  with proper cross-referencing, so the learning loop is inspectable and validatable
  end-to-end. It also demonstrates the ECL's own governance mechanism (canon evolving through
  a recorded ADR) working as designed — apt for a reference implementation.
- **Positive:** Backward compatible; every previously-valid ID still validates, and the
  Foundation artifacts are untouched.
- **Negative / cost:** `schemas/common.schema.json` — a Foundation artifact previously
  treated as frozen — is modified. This is acceptable only because it is ADR-governed and
  expand-only; the change is recorded here and in the schema's provenance.
- **Neutral:** Runtimes that persist worker runs/decisions/executions should adopt these
  prefixes; the reference corpus is the canonical example of their use.
