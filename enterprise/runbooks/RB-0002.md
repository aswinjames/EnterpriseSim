# RB-0002 — Promotions Cache Invalidation & Emergency Flush

| Field | Value |
|---|---|
| Runbook id | RB-0002 |
| Title | Promotions Cache Invalidation & Emergency Flush |
| Owner team | TEAM-008 (Promotions & Offers) |
| Apps | APP-008 (Promotions Engine) |
| Severity scope | Sev1–Sev2 |
| Related incidents | INC-2026-007, INC-2026-011, INC-2026-018 |
| Related knowledge | KN-304, KN-306, KN-312, KN-401 |

## Purpose

Invalidate or flush the APP-008 promotions cache when a promotion-window price or offer
change is not reflected at checkout, producing incorrect cart totals. This is the highest-
recurrence failure class at MCG: three incidents (INC-2026-007, -011, -018) traced to
promo-cache staleness. INC-2026-018 drove the systemic write-through fix and this standing
runbook; the pre-release check in RB-0009 exists to prevent the trigger.

## When to use (symptoms / alerts)

- Alert `promo-total-mismatch` — checkout (APP-003) reports `cart_total != sum(line_totals - promos)`.
- Customer/CS reports of "price at checkout doesn't match the promotion".
- Grafana **Promotions / Cache** shows `promo_cache_age_seconds` exceeding the offer's TTL,
  or a spike in `promo_cache_hit` for an offer that was just changed.
- A pricing (APP-007) or offer change deployed within the last 30 min and totals look stale.

## Preconditions

- TEAM-008 on-call, with break-glass access to the promo Redis (`promo-redis-prod`).
- `kubectl` context on the affected region; `mcg-flags` and `mcg-promo` CLI available.
- Know the affected **offer id(s)** and region — do NOT blind-flush the whole cache during a
  flash sale unless a full flush is explicitly authorized (it cold-starts every offer).

## Procedure

1. **Identify the stale key(s).** Prefer targeted invalidation over full flush:
   ```
   mcg-promo cache inspect --offer <OFFER_ID> --region <region>
   ```
   Compare `cached_price` against the source of truth in Pricing (APP-007):
   `mcg-pricing resolve --sku <SKU> --region <region>`.
2. **Targeted invalidation (preferred).** Publish an invalidation event for the offer; the
   write-through path (shipped after INC-2026-018) repopulates on next read:
   ```
   mcg-promo cache invalidate --offer <OFFER_ID> --region <region>
   ```
   Verify the key is gone: `redis-cli -h promo-redis-prod GET promo:offer:<OFFER_ID>:<region>` → `(nil)`.
3. **Bulk invalidation by promotion window.** If a whole campaign is stale:
   ```
   mcg-promo cache invalidate --campaign <CAMPAIGN_ID> --region <region>
   ```
4. **Emergency full flush (authorized, last resort).** Only with IC approval and outside a
   flash-sale peak, because it cold-starts all offers:
   ```
   redis-cli -h promo-redis-prod --scan --pattern 'promo:offer:*:<region>' | \
     xargs -n 500 redis-cli -h promo-redis-prod DEL
   ```
   Immediately pre-warm (step 5).
5. **Pre-warm after a flush.** Trigger the warmer so checkout does not hit a cold cache:
   ```
   mcg-promo cache warm --region <region> --active-only
   ```
6. **Confirm write-through is enabled.** The systemic fix must stay on; if a flag disabled it,
   re-enable:
   ```
   mcg-flags set promotions-engine promo.cache.write_through=true --region <region>
   ```

## Verification

- Checkout `promo-total-mismatch` alert clears; `cart_total` matches expected for a test cart
  containing the affected SKU/offer.
- `mcg-synthetics run checkout-promo --offer <OFFER_ID> --region <region>` passes.
- `promo_cache_age_seconds` back within TTL; hit ratio recovers after pre-warm.
- Reconcile a sample of in-flight carts: `mcg-promo audit --since 15m --region <region>` shows
  no remaining mismatches.

## Rollback

- Invalidation/flush is not reversible and needs no rollback (cache is derived state).
- If the trigger was a bad offer/pricing deploy, roll back that release per RB-0009 /
  RB-0013 rather than fighting the cache.
- If `write_through` was toggled and caused a latency regression, see RB-0012 before
  disabling it — disabling it reintroduces the staleness class.

## Escalation (follow-the-sun, Tier 0 checkout path)

- **T0:** TEAM-008 on-call owns cache correctness.
- **T1 (10 min):** Loop in TEAM-007 (Pricing) if the source price is wrong, and TEAM-004
  (Checkout) since totals are customer-visible — all three co-owned INC-2026-007/018.
- **Follow-the-sun:** NA → EU → APAC promo on-call; Sev1 during a flash sale pulls SRE
  (TEAM-032) as IC (RB-0011).
