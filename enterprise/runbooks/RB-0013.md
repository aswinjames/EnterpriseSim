# RB-0013 — Regional Pricing Rule Misconfiguration Rollback

| Field | Value |
|---|---|
| Runbook id | RB-0013 |
| Title | Regional Pricing Rule Misconfiguration Rollback |
| Owner team | TEAM-007 (Pricing) |
| Apps | APP-007 (Pricing Service) |
| Severity scope | Sev2–Sev3 |
| Related incidents | INC-2026-004 |
| Related knowledge | KN-303, KN-412 |

## Purpose

Roll back a bad regional pricing-rule configuration and re-resolve affected prices when a
rule change produces incorrect prices for a region. In INC-2026-004 a regional rounding-rule
misconfiguration produced off-by-one currency rounding in APAC for 22 minutes. Because
Pricing (APP-007) feeds Promotions (APP-008), a bad price also poisons the promo cache — so
this runbook ends by triggering the downstream promo-cache invalidation in RB-0002. Root
cause here is a **config change**, not code: the fix is a config rollback plus re-resolve,
not a redeploy. APP-007 is Java/PostgreSQL, Tier 0.

## When to use (symptoms / alerts)

- Alert `pricing-rule-anomaly` or `pricing-resolve-mismatch` for a specific region.
- CS / finance reports that displayed or charged prices are off by a rounding unit in one
  region (e.g., AU prices ending in the wrong minor unit).
- Grafana **Pricing / Rules** shows a rule-config version bump within the last ~30 min
  correlated with the anomaly; `pricing_rule_version` gauge changed for `region=APAC`.
- Downstream: Promotions (APP-008) and Cart (APP-004) preview totals inherit the wrong price.

## Preconditions

- TEAM-007 on-call; `kubectl` context on the affected region; `mcg-pricing` CLI and read
  access to the pricing PostgreSQL (`pricing-db-prod`, read replica for inspection).
- Pricing Service runs in namespace `pricing` as deploy/pricing-service.
- Rule configs are versioned in the `pricing_rule_config` table and served from an in-memory
  ruleset refreshed on config publish; each version has an immutable `config_version` id.
- Know the affected **region** and, ideally, the suspect `config_version`.

## Procedure

1. **Identify the active and previous rule-config versions.** Find what is live and what it
   replaced:
   ```
   mcg-pricing config list --region <region> --last 5
   ```
   Note the current `config_version` (e.g., `PRC-CFG-20260205-3`), its publish time, and the
   last-known-good version immediately before it.
2. **Confirm the bad rule.** Diff the suspect version against the prior good one:
   ```
   mcg-pricing config diff --region <region> \
     --from <good_version> --to <current_version>
   ```
   For INC-2026-004 the diff shows a changed rounding rule (e.g., rounding mode / minor-unit
   scale) for the region. Confirm against a known SKU:
   ```
   mcg-pricing resolve --sku <SKU> --region <region> --explain
   ```
   The `--explain` output names the rule and rounding step producing the off-by-one value.
3. **Roll back the pricing-rule config (primary mitigation).** Re-activate the last-known-good
   version; this is a config activation, not a deploy:
   ```
   mcg-pricing config rollback --region <region> --to <good_version> \
     --reason "INC-2026-### regional rounding misconfig"
   ```
   The service reloads the active ruleset from the restored version.
4. **Force a ruleset reload if needed.** If pods have not picked up the restored version
   within ~30s, refresh the in-memory ruleset without a restart:
   ```
   kubectl -n pricing exec deploy/pricing-service -- \
     curl -s -XPOST localhost:8081/admin/rules/reload
   ```
5. **Re-resolve affected prices.** Recompute the region's resolved prices so the correct
   values propagate to caches and downstream consumers:
   ```
   mcg-pricing reresolve --region <region> --since <config_publish_time> \
     --scope affected-skus
   ```
   Scope to affected SKUs (those touched by the bad rule) rather than the whole catalog to
   keep the re-resolve fast.
6. **Invalidate the downstream promo cache.** Pricing feeds Promotions, so the promo cache
   now holds the wrong price. Trigger the promo-cache invalidation per RB-0002 for the region
   (targeted, not a full flush during a sale):
   ```
   mcg-promo cache invalidate --region <region> --reason "pricing rollback INC-2026-###"
   ```
   Hand off to TEAM-008 if a campaign-scoped or full flush is required (RB-0002).
7. **Verify the config-management guardrail.** Confirm the bad version is marked so it cannot
   be re-activated by an automated job:
   ```
   mcg-pricing config quarantine --version <bad_version> --reason "INC-2026-###"
   ```

## Verification

- `mcg-pricing resolve --sku <SKU> --region <region> --explain` returns the correct rounded
  price using the restored rule version.
- `pricing-resolve-mismatch` / `pricing-rule-anomaly` alerts clear; `pricing_rule_version`
  gauge shows the restored version for the region.
- `mcg-synthetics run pricing-resolve --region <region>` passes for a basket of SKUs.
- Downstream: Cart (APP-004) preview and Checkout (APP-003) totals show correct prices;
  `mcg-promo audit --since 30m --region <region>` reports no remaining price mismatches.
- Reconcile any orders placed during the window with finance (flag for adjustment if charged
  amounts differed) — record the affected order range in the incident.

## Rollback

- The mitigation *is* a rollback (to the last-known-good config version); if the restored
  version also proves wrong, roll to the next-earlier known-good version and re-resolve again.
- No schema change is involved (config-row activation only), so there is no DB down-migration.
- Do not attempt to hand-edit the live ruleset in place — always activate a versioned
  config so the change is auditable and reversible (CANON §4.5, no manual prod changes).
- The durable fix is a corrected rule config shipped via the normal review flow, plus a
  pre-publish validation check for rounding rules (see KN-412).

## Escalation (follow-the-sun, Tier 0)

- **T0 (0–10 min):** TEAM-007 regional on-call owns the pricing config and acts as Ops lead.
- **T1 (10 min):** Loop in TEAM-008 (Promotions) for the downstream cache invalidation, and
  TEAM-004 (Checkout) since totals are customer-visible.
- **Follow-the-sun (Tier 0):** rotate on-call/IC NA (`oncall-pricing-na`) → EU
  (`oncall-pricing-eu`) → APAC (`oncall-pricing-apac`); INC-2026-004 impacted APAC, so the
  APAC holder is likely first responder. Keep `#inc-pricing-rules` as the single source of truth.
- **T2 (Sev2 or > 20 min):** engage SRE (TEAM-032) as Incident Commander and follow RB-0011.
