# RB-0003 — Payments PSP Failover & Routing

| Field | Value |
|---|---|
| Runbook id | RB-0003 |
| Title | Payments PSP Failover & Routing |
| Owner team | TEAM-009 (Payments) |
| Apps | APP-012 (Payments Service) |
| Severity scope | Sev1–Sev2 |
| Related incidents | INC-2026-009 |
| Related knowledge | KN-305, KN-402 |

## Purpose

Restore payment authorization when the primary payment service provider (PSP) degrades, by
failing authorization routing over to the secondary PSP without breaching the PCI boundary
or double-charging customers. APP-012 is a Tier-0 PCI service on the `golden-path-jvm-pci`
pipeline; cardholder data never leaves its boundary and no card PAN is written to logs,
flags or the incident channel. This runbook operationalizes the response to INC-2026-009
(primary PSP degraded, authorization p99 spiked for 50 minutes across NA and LATAM before
failover routing engaged) and its postmortem KN-305.

## When to use (symptoms / alerts)

- PagerDuty alert `payments-auth-p99-high` (`auth_latency_p99 > 2500ms (5m)`) or
  `payments-psp-error-ratio` (`psp_auth_error_ratio{psp="primary"} > 5% (5m)`).
- Grafana dashboard **Payments / PSP** shows `psp_auth_success_ratio{psp="primary"}` sagging
  while `circuit_breaker_state{psp="primary"}` moves toward `half_open`/`open`.
- Checkout (APP-003) `payment.authorize` spans time out or return `PSP_TIMEOUT` /
  `PSP_5XX`; abandoned-order rate climbs on the Storefront funnel board.
- PSP status page or account manager confirms a provider-side degradation.

## Preconditions

- You are on the TEAM-009 on-call rotation (or the follow-the-sun holder for a Tier-0 page).
- `kubectl` context set to the affected region: `kubectl config use-context mcg-<region>-prod`.
- Payments Service runs in namespace `payments`; secondary PSP credentials are already
  provisioned in the platform secret manager (`mcg-secrets get payments/psp/secondary`) —
  never printed to a terminal.
- You hold break-glass authorization for a PSP routing change (Tier-0/PCI, ≥2 approvers per
  CANON §7.5) recorded in the incident channel `#inc-payments-psp`.

## Procedure

1. **Confirm the primary PSP is the fault domain, not MCG.** Isolate provider health from
   our own error budget:
   ```
   mcg-payments psp health --provider primary --region <region>
   ```
   Look for elevated `upstream_5xx` / `upstream_timeout` with our egress and mTLS handshake
   healthy. If MCG-side, this is not a failover — go to Escalation.
2. **Check circuit breaker state.** The Resilience4j breaker should already be shedding load:
   ```
   kubectl -n payments exec deploy/payments-service -- \
     curl -s localhost:8081/actuator/circuitbreakers | jq '.psp_primary'
   ```
   Expect `state: OPEN` or `HALF_OPEN` under a real degradation. If still `CLOSED` while
   errors are high, force it open so retries stop hammering the primary:
   ```
   mcg-payments breaker trip --provider primary --region <region>
   ```
3. **Fail authorization routing to the secondary PSP.** Shift the active auth route; capture
   remains on the primary until it recovers to avoid orphaning in-flight auths:
   ```
   mcg-flags set payments-service payments.psp.active_route=secondary --region <region>
   mcg-flags set payments-service payments.psp.capture_route=primary_then_secondary --region <region>
   ```
4. **Guarantee idempotency on retry.** Retried authorizations MUST reuse the original
   idempotency key so a slow-but-successful primary auth is not duplicated on the secondary.
   Confirm the key-preservation guard is on:
   ```
   mcg-flags set payments-service payments.retry.preserve_idempotency_key=true --region <region>
   mcg-payments idempotency verify --window 15m --region <region>
   ```
   The command must report zero `duplicate_authorization` events. If any appear, HALT the
   failover and escalate — double-charge risk outranks availability.
5. **Cap secondary blast radius.** The secondary has lower negotiated throughput; enable the
   adaptive concurrency limit so we do not degrade it too:
   ```
   mcg-flags set payments-service payments.psp.secondary.max_tps=400 --region <region>
   ```
6. **Verify the PCI boundary held.** Confirm no cardholder data crossed a boundary during the
   route change (tokens only; PAN stays in the PSP vault path):
   ```
   mcg-payments pci-boundary check --since 20m --region <region>
   ```
   Any `pan_leak_suspected` finding is a Sev1 security escalation to TEAM-040 immediately.

## Verification

- `psp_auth_error_ratio{psp="secondary"} < 1%` and `auth_latency_p99 < 1200ms` for 5
  continuous minutes on the Payments / PSP board.
- `mcg-synthetics run payment-authorize --region <region>` returns `200` with
  `psp=secondary`.
- `mcg-payments idempotency verify --window 30m` reports zero duplicate authorizations.
- Reconcile captures: `mcg-payments recon --since 30m --region <region>` shows every auth
  has at most one capture and no `orphaned_auth` records.
- Abandoned-order rate on the Storefront funnel board returns to baseline.

## Rollback

- **Fail back to primary once healthy.** When `mcg-payments psp health --provider primary`
  is green for 10 minutes, restore routing and reset the breaker:
  ```
  mcg-flags set payments-service payments.psp.active_route=primary --region <region>
  mcg-payments breaker reset --provider primary --region <region>
  ```
- Fail back gradually — set `active_route=primary` for a 10% canary cohort first
  (`payments.psp.primary_canary_pct=10`) before full cutover, watching the error ratio.
- Do **not** revert `payments.retry.preserve_idempotency_key`; it must stay on permanently.
- If a hotfix image was deployed during response, `kubectl -n payments rollout undo
  deploy/payments-service` and confirm the prior `v<semver>` tag; PCI changes need ≥2
  approvals including Security Eng before re-deploy.

## Escalation (follow-the-sun, Tier 0)

- **T0 (0–10 min):** TEAM-009 regional on-call is Incident Commander for Payments.
- **T1 (10 min, unresolved):** Engage TEAM-040 (Security Engineering) for any PCI-boundary
  question and the PSP account manager for provider-side confirmation.
- **Follow-the-sun handoff** for Tier-0 pages: NA (`oncall-payments-na`) → EU
  (`oncall-payments-eu`) → APAC (`oncall-payments-apac`); rotate IC at the regional boundary
  and keep `#inc-payments-psp` as the single source of truth.
- **T2 (20 min or Sev1):** Engage SRE (TEAM-032) as Incident Commander and follow RB-0011.
